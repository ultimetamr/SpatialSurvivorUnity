# 2.7.2 · 房间漫游

本轮重点是默认安全边界限制用户移动。扫描房间后使用魔法主题模型替换地面、墙面及家具的功能应继续保留；2.7.1 移除房间主题的改动已纠正。

## 房间替换保留

恢复 `SurvivorMrSession` 的主题初始化、场景语义映射、全量快照更新和销毁清理；地面、墙面、门窗及已支持的家具继续呈现魔法主题。默认开启，沿用原有 `RealmWardens.RoomTheme` 开关偏好，MR 设置中的“魔法场景：开/关”恢复可用。

原始扫描网格仍不可见，碰撞和导航数据继续工作；关闭主题也不会显示原始网格。房间主题不新增碰撞体、不写入深度遮挡怪物或 UI。保留 2.7.1 的完整地面融合、随走动更新导航和持续追击修复。

## 默认边界策略

检查发现旧 2.7.0 的 `mrSafeguard` 和 Android 应用 metadata `enable_mr_safeguard` 为 0，虽然透视已经开启，仍采用 SDK 默认 VR 安全策略。当前 Unity 配置与初始化明确使用 `mrSafeguard=true`，构建和导出要求最终清单 `enable_mr_safeguard=1`、`enable_vst=1`。这项修正已经包含在 2.7.1，并随本次主题恢复继续保留。

依据为项目实际使用的 PICO Unity SDK 6.1.1 源码：`PXR_ManagerEditor.cs` 中的 MR Safeguard 提示和 `PXR_BuildProcessor.cs` 的应用 metadata 生成逻辑。SDK/系统执行最终策略。应用直接读取头显位置，没有开局圆圈内的玩家位置钳制；没有调用关闭 Guardian 或强制隐藏系统边界的接口。

当前不能仅根据静态配置宣称所有头显上边界问题已经解决。需要在新包上验证 MR 透视中的连续走动，以及系统是否仍采用已保存的小范围活动区；如仍提示小范围边界，需在头显活动区域设置中按实际空地重新校准。定位丢失和系统暂停期间仍停止战斗。
